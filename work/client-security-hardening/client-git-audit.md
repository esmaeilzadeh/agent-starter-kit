# AskIt file ownership in client Git

Source: published kit `88035127763fb1436775c13c941fbcba7484d581`. Installed into an empty disposable Git repository with dependency preparation disabled. Inspected stageable and ignored untracked files using Git itself, and traced upgrade, setup, verification scaffolding, and sync source. The installation produced 146 stageable paths and 134 ignored files.

| Surface | Published behavior | Required client Git treatment |
| --- | --- | --- |
| Runtime package `_ask/` | Ignored on fresh install. Upgrade does not apply the same package ignore update. Legacy customized settings may still live inside it. | Ignore installed package files. Migrate customized inputs into a project-owned location before refreshing. |
| Protocol and launcher | `.agents/ask/` (52 files), root `ask`, `.ask/README.md`, and `.ask.env.example` are stageable although installed by the kit. Older versions also installed root kit guide stubs. | Ignore stock files. Preserve pre-existing project files at any colliding path. |
| Agent and editor outputs | Codex stage skills (11) and generated runtime agents are stageable. Cursor stock rules, commands, hooks, and skill projections are stageable. Consumer tooling can coexist in these directories. | Ignore only the paths the kit owns, including generated outputs. Keep independently maintained files and custom hooks trackable. Separate mixed runtime config or treat it as an explicitly maintained project file when it contains project policy. |
| Project configuration | Fresh install makes the project skill manifest, root `AGENTS.md`, and `.gitignore` stageable. Setup and scaffolding can add public tracker metadata, CheckPlan, skill lock data, and model/stage overrides. | Commit project-owned files and keep existing custom rules, commands, skills, and overlays trackable. Use a shared managed block in project `.gitignore` and preserve consumer rules. |
| Local state | Fresh install ignores `.ask.env` and tracker context. A candidate CheckPlan path is separate from the committed CheckPlan. Verification reports, caches, locks and retained logs can be created after installation. | Keep secrets out of the worktree where possible. Ignore temporary state and candidate files. Keep canonical plans, specs, workstream state and deliberately archived evidence trackable. |
| Existing tracked files | Git ignores do not affect files already in the index. A stock copy already committed remains tracked after upgrade. | Classify before modifying the index. Automatically untrack only unchanged files whose kit ownership is proven. Preserve bytes on disk and leave the resulting changes for the client's ordinary upgrade commit. Refuse ambiguous collisions before writes. |

Of the 146 stageable paths in the fresh fixture, three are intended project inputs: `.gitignore`, `AGENTS.md`, and `.agents/ask.local/skills/manifest.yaml`. The remaining 143 are stock or generated kit outputs, including the fresh stock Cursor hook configuration. An existing customized hook configuration is project input.

Live setup, external skill installation, runtime discovery, and migrations were not executed in this audit. The setup and generated-state rows come from code inspection. The separate Cursor rule preservation repair records a reproduced upgrade defect.
