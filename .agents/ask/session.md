# AskIt session instructions

- Start on the AskIt path. Before starting or resuming work, run `./ask access-check` unless the session hook already checked access. If it fails, report the blocked path and stop project work until access is restored.
- For a continuation request, inspect the branch, workstream artifacts, inner-loop state, and recent commits. Resolve an explicitly named workstream first. Otherwise prefer a matching checked-out `agent/<work-id>`. Resume only its authorized stage and task. Report an explicit stop or terminal endpoint and preserve prior approvals. Ask if the target or authorization evidence is ambiguous.
- Before using any stage, classify each deliverable against accepted behavior and state the route and evidence. Reproduce reported defects before editing or adding a regression. Use the focused bug-fix path for a reproduced defect and separate bug and feature workstreams for mixed requests. Read `_ask/policies/workflow.md` for the routing rules.
- For a new feature, state whether the destination is clear. Use 00 Explore when it is foggy, and record its handoff before 01 Grill. When the destination is already clear, skip 00, omit `explore-map.md`, and record `Explore skipped: destination already clear.` in the intent. Follow the entry decisions in the workflow policy.
- Before labor, run `./ask check-clean`. Resolve any dirty paths with the human. Start a workstream from `develop` with `./ask start-work <work-id>`. Keep one plan per `agent/<work-id>` branch and maintain its Engineering Model. Prepare pinned skills with `./ask prepare` when needed. After changing stage or binding sources, run `./ask sync`.
- Present the complete feature intent and assumptions as **Approve** or **Request changes** choices. Record the submitted choice with `./ask confirm-intent`. Use `./ask check-workstream <work-id> --implementation` before feature implementation. Follow the authorized plan, commit each meaningful step, and use `.agents/ask/task-loop.md` for an active TaskGraph.
- Before claiming completion, run `./ask verify` and record the result against the verified commit. For feature acceptance use `./ask check-workstream <work-id> --acceptance` and present **Accept workstream** or **Request changes**. Keep prior approvals unless What, Why, or an assumption changes.
- An explicit request to go off-path applies to the current chat only. Request routing and reproduction still apply. Read the relevant stage contracts under `.agents/ask/stages/` and policies under `_ask/policies/`.
